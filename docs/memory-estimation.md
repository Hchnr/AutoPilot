# 显存估算

## 目的

显存估算器判断给定配置（模型 + 精度 + TP + PP + Batch 参数）是否能装入 GPU 显存。这是首要剪枝条件 — 不满足的配置直接丢弃。

## 组成部分

推理过程中 GPU 显存由三大部分消耗：

```
┌─────────────────────────────────────────┐
│           GPU 显存布局                    │
├─────────────────────────────────────────┤
│  模型权重           （静态）              │
│  KV Cache          （动态）              │
│  运行时开销         （半静态）            │
│  安全余量           （10%）              │
└─────────────────────────────────────────┘
```

## 公式

### 模型权重显存（每卡）

```
weight_per_gpu = 参数量 × 每参数字节数 / TP / PP
```

每参数字节数：
| 精度 | 字节数 |
|------|--------|
| bf16/fp16 | 2 |
| fp8/int8  | 1 |
| int4      | 0.5 |

示例：Qwen3-32B，FP8，TP=4，PP=1
```
32 × 10⁹ × 1 / 4 / 1 = 8 × 10⁹ 字节 ≈ 7.45 GB 每卡
```

### KV Cache 显存（每卡）

每个 Token 在 KV Cache 中占用：
```
kv_per_token = 2 × num_layers × num_kv_heads × head_dim × kv_dtype_bytes / TP
```

因子 2 是因为 K 和 V 两个张量。

KV Cache 总量：
```
kv_total = kv_per_token × max_num_seqs × context_length
```

其中 `context_length` 设为 `min(input_p99 + output_p99, max_model_len)`。

示例：Qwen3-32B，TP=4，bf16 KV，64 并发 × 7000 上下文
```
kv_per_token = 2 × 64 × 8 × 128 × 2 / 4 = 65,536 字节
kv_total = 65,536 × 64 × 7000 ≈ 27.3 GB
```

### 运行时开销

固定估算，覆盖：
- 前向传播中的激活内存
- CUDA Graph 捕获缓冲区
- 框架内部缓冲区（vLLM/SGLang 调度器、Tokenizer 等）
- 临时张量

默认值：H 系列 vLLM **7 GB**，小 GPU 或 SGLang **5-6 GB**。

### 安全余量

在小计上乘以 10%，用于应对：
- 显存碎片
- 峰值 vs 平均分配差异
- 长序列时的意外峰值

### 总公式

```
total = (模型权重 + KV Cache + 运行时开销) × 1.10
```

## 可行性判断

配置**可行**的条件：
```
total ≤ gpu_memory_gb × 0.95
```

0.95 因子为 OS/驱动预留 5% 显存。

## 参数对显存的影响

| 变更 | 显存影响 | 权衡 |
|------|----------|------|
| TP ↑ | 权重 ↓，KV ↓ | 需要更多 GPU，通信开销增加 |
| PP ↑ | 权重 ↓ | Pipeline 气泡，延迟增加 |
| FP8 精度 | 权重 ↓ 50% | ~0.5% 质量损失 |
| FP8 KV Cache | KV ↓ 50% | ~0.2% 质量损失 |
| max_num_seqs ↓ | KV ↓ | 吞吐降低 |
| 上下文长度 ↓ | KV ↓ | 无法服务长请求 |

## 局限性

- 激活内存作为运行时开销的一部分近似处理，未逐层计算
- 未建模 PagedAttention（vLLM 块级 KV 管理）的显存节省
- Prefix Cache 共享内存未显式建模
- 未考虑 Speculative Decoding 的额外显存开销
