# 闭环控制策略

## 概述

Reconciler 监控运行时 Telemetry 并决定当前部署是否需要调整。设计理念是**保守优先** — 不必要的变更成本（服务重启、短暂降级）高于多等一个观测窗口的成本。

## Telemetry 输入

每条 Telemetry 记录代表一个 5 分钟观测窗口：

```json
{
  "timestamp": "2026-06-20T10:05:00Z",
  "request_rate": 15.0,
  "queue_depth": 12,
  "p95_ttft_ms": 750,
  "p95_itl_ms": 38,
  "gpu_utilization": 0.78,
  "kv_cache_utilization": 0.80,
  "oom_count": 0,
  "error_rate": 0.001
}
```

## 决策逻辑

### 信号检测

| 信号 | 阈值 | 需要连续窗口数 |
|------|------|---------------|
| TTFT SLO 违反 | p95_ttft > 800ms | 3 |
| ITL SLO 违反 | p95_itl > 45ms | 3 |
| KV Cache 临界 | 平均 > 95% | 1（立即）|
| KV Cache 偏高 | 平均 > 90% | 1 |
| GPU 低利用率 | 平均 < 25% | 5 |
| OOM 事件 | count > 0 | 1（立即）|

### 操作映射

```
TTFT 违反  → 降低 max_num_seqs（如可能）→ 否则扩容
ITL 违反   → 扩容
KV 临界    → 激进降低 max_num_seqs（× 0.75）
KV 偏高    → 切换 FP8 KV Cache（如未启用）
GPU 低     → 缩容（最小 1 副本）
OOM        → 激进降低 max_num_seqs（× 0.6）
```

### 优先级

每次 Reconcile 周期只执行一个操作。优先级顺序：
1. OOM（安全关键）
2. KV Cache 临界（预防 OOM）
3. SLO 违反（用户可感知影响）
4. KV Cache 偏高（优化）
5. GPU 低利用率（成本节省）

## 安全机制

### 连续窗口确认

不基于单次波动采取操作。扩容需要 3 个连续窗口；缩容需要 5 个。可以防止：
- 对瞬态负载尖峰的过度反应
- 扩容和缩容之间的振荡

### 非对称阈值

缩容比扩容更难触发：
- 扩容：3 窗口 × 5 分钟 = 15 分钟持续违反
- 缩容：5 窗口 × 5 分钟 = 25 分钟持续低利用率

这种不对称是刻意的 — 资源不足（SLO 违反）的代价高于轻微过配（浪费 GPU）的代价。

### 冷却期

任何操作执行后，强制 3 个窗口（15 分钟）的冷却期。冷却期内不允许新操作，无论信号强度如何。这样做的目的：
- 让上一次操作有时间生效
- 防止多个变更叠加
- 给系统稳定时间

### 单次单操作

即使检测到多个信号，也只输出一个操作。这使得：
- 更容易归因每次变更的效果
- 避免冲突调整

### 风险分级

| 风险等级 | 操作类型 | 特征 |
|----------|----------|------|
| 低 | scale_replicas, adjust_max_num_seqs | 无需重启，可立即回滚 |
| 中 | change_kv_cache_dtype | 需要重启，短暂停机 |
| 高 | change_tp, change_pp, change_precision, change_gpu_pool | 重大重配置，较长停机 |

高风险操作标记为 `requires_restart: true`，建议人工确认后执行。

## 防震荡示例

```
窗口 1: TTFT=850ms（违反）     → 无操作 (1/3)
窗口 2: TTFT=920ms（违反）     → 无操作 (2/3)
窗口 3: TTFT=780ms（正常）     → 计数器重置 (0/3)
窗口 4: TTFT=900ms（违反）     → 无操作 (1/3)
窗口 5: TTFT=950ms（违反）     → 无操作 (2/3)
窗口 6: TTFT=880ms（违反）     → 操作：scale_replicas +1
窗口 7-9: 冷却期               → 无操作（不管信号如何）
窗口 10: TTFT=600ms（正常）    → 系统已稳定
```

## 局限性

- 固定 5 分钟窗口粒度（不自适应流量模式）
- SLO 阈值目前硬编码（应从 plan 的 SLO 配置加载）
- 不支持预测性扩容（仅反应式）
- 无回滚机制（如果操作使情况恶化，依赖下一个 reconcile 周期）
